Web installer

This is the experimental WebUSB installer for Rockbox on Shanling M3X. Connect your player, verify a matching release and install from your browser. The command-line installer remains the hardware-tested fallback.

Experimental browser installer

Browser device operations, including rooting, have not been hardware-tested. Rooting changes the boot partition and Android security; a failed flash can prevent booting or require EDL recovery. Back up music and settings separately. This is not official Rockbox or Shanling firmware.

Boot-partition writes are disabled in this build pending browser EDL and recovery validation.

Prerequisites

  • Shanling M3X, firmware 1.75, Android 7.1.1/API 25. Other models and firmware versions are refused.
  • An up-to-date desktop Chromium browser, such as Chrome or Edge, over HTTPS or localhost. Safari and Firefox lack WebUSB.
  • A reliable data-capable USB cable. Connect directly to the computer; avoid unreliable hubs and virtual-machine USB passthrough.
  • USB debugging enabled, Android running, Rockbox stopped and battery charged to at least 50%.
  • For ordinary Rockbox installation: Magisk root and the existing GPIO18/19 audio device-tree fix.

Linux may require USB permissions; Windows needs a compatible USB driver. Do not replace drivers blindly. Stop desktop ADB if it owns the USB interface. Browser/OS driver interoperability has not yet been validated on this player.

If the player is already rooted, use the ordinary installation path. Root preparation is a separate development path; do not re-root a working installation merely to test this page.

Connecting the device

Return to Android and stop Rockbox. Press Connect M3X, select your player in the browser's USB chooser, then accept the USB-debugging prompt on the player. If already rooted, also accept any Magisk ADB permission prompt.

No player connected.

The browser key stays in memory, not localStorage or IndexedDB. Disconnecting or reloading requires fresh authorization. Device identity is checked before requesting root. No USB access or installation occurs automatically.

Obtaining a release

Download the installer ZIP and its matching corresponding-source ZIP from the experimental release. Select the attached installer ZIP below, not GitHub's automatic source download.

The entire archive SHA-256 is pinned to a reviewed release. Its manifest and every bundled file are verified again before installation. Files are processed locally, not uploaded to a server.

Installing Rockbox

This path runs the existing verified, transactional installer as root. It does not flash firmware. Updates preserve music and current settings and create a rollback snapshot. Keep the tab and USB cable connected until completion.

Save the backup path printed in the operation log. Boot autostart remains disabled; Android stays the default boot. Root access does not make this a complete sandbox: run only trusted plugins and Lua scripts.

Restoring an installation

To roll back Rockbox, use the snapshot name printed by the installer. This restores installation/settings state from that snapshot, not the boot partition. Restoring an older snapshot also restores its older loader and security limits.

Root preparation

Development path, not validated one-click rooting. M3X fastboot cannot flash, boot, reboot or continue. Do not use generic OEM-unlock, factory-reset or fastboot-flashing recipes.

Supply your stock boot.img extracted from firmware 1.75, the official Magisk 30.7 APK and the exact verified MSM8937 Firehose programmer. These files are not bundled or sent to a server.

Firmware and APK hashes are pinned. Magisk patches a staged file as the unprivileged ADB shell; the browser validates the kernel/header and changes only four conflicting device-tree pin lists. This file-patching invocation and its resulting image are untested on an unrooted player. Unsupported output fails closed.

Rooting may weaken verified-boot and force-encryption policy. No erase command is issued, but that is not a guarantee against data loss. A boot backup does not back up userdata. Keep a separate music/settings backup and a working recovery environment.

EDL connection and recovery backup

Root installation uses Qualcomm EDL, not fastboot. Entry reboots the player; grant browser USB permission again for 05c6:9008. Connect only this player. Rebooting is always an explicit action.

Read-only diagnostics

Already rooted and validating browser transport? Select the verified programmer above and use this separate path. It creates no root candidate or flash authorization. The programmer is executed in device RAM; no partition-write command is issued.

Saving the recovery backup

Sahara chip serial must match the checked ADB device. Programmer hash, eMMC identity and GPT CRC/layout are verified. Root installation additionally requires the entire current boot partition to match stock 1.75. Read-only diagnostics can back up an already-rooted player's current boot without authorizing writes.

Save both the boot backup and recovery JSON. The record contains device identity; keep it private. Reopening the saved file proves it matches the actual device read. Downloads alone do not authorize flashing.

Boot flash and restore

Disabled on this public site. Browser boot writing and recovery have not been validated. Physical EDL re-entry when Android cannot boot is not established; adb reboot edl requires a booting Android system.

Only the verified boot partition can be written. No userdata, system, recovery or GPT writes, unlock, erase or automatic reboot. A full readback must match before success. Do not disconnect, close the tab or power off during a write.

Prepare and verify a saved backup first.

Restoring the boot backup

After failure, stay in EDL and restore with the prepared native recovery environment. No automatic reboot or retry occurs. Browser recovery across a closed tab is not implemented.

Post-installation

After ordinary Rockbox installation, open Rockbox from Android and begin at low volume. Use Return to Android in Rockbox's main menu to exit. Save the installer snapshot path for rollback.

A verified boot readback would not by itself prove Android bootability, root or audible audio. Any future developer root test must explicitly return to Android, finish Magisk setup and verify root before Rockbox installation.

Disconnect when finished. Revoke USB-debugging authorization and disable debugging on the player after use.
