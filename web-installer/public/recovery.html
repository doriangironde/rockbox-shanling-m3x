M3X boot recovery: prepare before flashing

Browser rooting is not hardware-validated. Normal builds disable boot writes. The recorded adb reboot edl requires Android to boot. Physical EDL re-entry without Android has not been validated. Do not enable boot writes until a no-Android recovery-entry method is established.

Keep these offline

  • A separately saved music/settings backup. A boot backup does not contain userdata.
  • Your complete 64 MiB boot backup and private recovery JSON. Confirm both downloaded successfully. Reopen the boot file in the installer to verify its SHA-256.
  • The exact verified MSM8937.mbn programmer and stock M3X 1.75 firmware.
  • A working native linux-msm/qdl installation, tested USB access and an explicitly tested EDL-entry method.

Firmware, programmer and Magisk binaries are user-supplied, not bundled here. A programmer hash identifies the recorded working file; it does not grant redistribution rights.

If the browser connection is lost

No automatic reboot or retry occurs. Stay in EDL after a partial/failed flash. In-session browser restore requires its own typed confirmation and full readback. Recovery across a closed tab is not implemented; use native QDL.

Disconnect/release browser USB first. Connect only the same M3X matching the saved serial and disk identity. Never restore another device's backup or guess a partition address.

The commands below WRITE the boot partition. Use them only for the verified M3X 1.75 layout (512-byte sectors, boot LBA 790528, 131072 sectors). Substitute the name of your saved full boot backup for YOUR_SAVED_BOOT_BACKUP.bin. Use a fresh output filename for readback; do not overwrite the original backup.

qdl --skip-reset --storage=emmc MSM8937.mbn write 0/790528+131072 YOUR_SAVED_BOOT_BACKUP.bin
qdl --skip-reset --storage=emmc MSM8937.mbn read 0/790528+131072 m3x-restored-boot-readback.bin

--skip-reset keeps EDL active. Both files must be exactly 67,108,864 bytes, and both full SHA-256 values must match backupSha256 in your recovery JSON. Inspect your QDL version's help first; behavior across versions/OS drivers is not validated.

python3 -c 'import hashlib,pathlib; [print(p.stat().st_size,hashlib.sha256(p.read_bytes()).hexdigest(),p) for p in map(pathlib.Path,["YOUR_SAVED_BOOT_BACKUP.bin","m3x-restored-boot-readback.bin"])]'

On mismatch, do not reboot. Native EDL read/write was used during original port bring-up, but browser-generated backups/images and these handoffs have not been tested on hardware. Readback alone does not prove bootability.

After a verified restore, explicitly disconnect/power-cycle. Restoring stock boot removes the newly installed Magisk root/audio fix; a diagnostic backup instead restores that player's previously backed-up boot image. The Magisk manager APK may remain installed.
